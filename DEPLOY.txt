REMOTE MULTIPLAYER ON VPS

Coolify:

  Deploy this repo as a Dockerfile app.
  Container port: 80
  Persistent storage: mount a volume at /data
  Public domains: velvetgrimore.xyz, www.velvetgrimore.xyz, vg.highfunctioningchaos.living
  Current host: 159.198.39.151
  SSH port for server maintenance: 22022
  Coolify app label: coolify.resourceName=velvet-grimore

The included Dockerfile runs:

  node server.js

with PORT=80 inside the container.
Table data is written to DATA_DIR, which defaults to /data in the Docker image.

Current production routing is Coolify/Traefik -> the app container -> node server.js.
This GitHub repo is the source of truth for future Coolify rebuilds.

Direct VPS:

Copy this entire folder to:

  /var/www/velvetgrimore

Install Node.js 18+ on the VPS if needed.

Install the service:

  cp deploy/velvetgrimore.service /etc/systemd/system/velvetgrimore.service
  systemctl daemon-reload
  systemctl enable --now velvetgrimore

Check it:

  systemctl status velvetgrimore
  curl http://127.0.0.1:8765/api/health

Nginx:

Use deploy/nginx-velvetgrimore.conf as the base server block, or add this location to the existing site:

  location / {
      proxy_pass http://127.0.0.1:8765;
      proxy_http_version 1.1;
      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header X-Forwarded-Proto $scheme;
  }

Reload nginx after config test:

  nginx -t
  systemctl reload nginx

In the app:

1. Open Admin -> Settings -> Remote Multiplayer.
2. Leave Backend URL as the site URL.
3. Click Create.
4. Share the table code with the player.
5. Player opens /player/player.html, enters their table name and role, then joins.
6. Use the lobby roster to confirm each seated player is online and ready.
7. The Warden seat controls shared table state; player and spectator seats receive updates but cannot overwrite the shared snapshot.

DATA MODEL
All app data is browser-local unless a Discord webhook is configured.
The Intimate Table layer stores scene chat, consent ceiling, heat, and want/boundary cards in browser storage.
In VPS backend mode, synced table snapshots and lobby player records are also stored on the VPS in DATA_DIR/tables.json.
Multiplayer V2 adds online/idle presence and Warden-only shared-state writes to prevent player screens from overwriting the table snapshot.

Before real play:
1. Open Admin -> Settings -> Backup Everything.
2. Save the exported JSON somewhere safe.
3. Repeat after each major campaign-editing session.

DISCORD
Discord webhook integration is optional. If enabled, selected events are sent to Discord.
