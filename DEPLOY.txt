VELVET GRIMOIRE - MEMBERS DEPLOYMENT

The authoritative source is the app/ Git checkout, repository worobi/velvetgrimore.xyz, main branch.
The parent deploy/ and web/ folders are historical static releases. Do not copy them into the members app.

Required Coolify settings:
- Dockerfile build from repository root
- Port 8080
- HTTPS at velvetgrimore.xyz; www redirects to the canonical hostname
- Persistent host storage /data/velvet-grimoire mounted at /data
- Volume owned by container user UID/GID 1000
- Health check GET /api/health on port 8080, expecting 200

Initial migration:
1. Back up the live container's /data directory and validate both legacy JSON files.
2. Prepare the new image before stopping the old app.
3. Stop writes on the old app and take a final data copy.
4. Copy that data to the protected host volume and set ownership to 1000:1000.
5. Deploy the reviewed full Git commit through Coolify.
6. Verify health, login, no anonymous table access, the persistent mount, account/table counts, and a database backup.

The app imports legacy files once into /data/velvet.sqlite. Saved files remain outside the web root. Never remove or replace the persistent volume during a routine deployment.

The repository includes deploy/coolify-members.php for this application's one-time configuration and deployment through the installed Coolify framework. It requires the exact reviewed 40-character Git commit. Run it only after preparing the data mount.

Invitation email:
The owner signs in and opens Member Administration, then connects the existing Spacemail mailbox. No real invitation can be sent until this succeeds. No SMTP password belongs in source control or chat.

Backups:
Run node scripts/backup.js inside the app container. It writes a consistent database backup and mail.key under /data/backups. The supplied host wrapper can be run nightly through cron. Keep off-host copies separately for whole-server recovery.
